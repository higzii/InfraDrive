# Архитектура проекта InfraDrive

## 1. Назначение и границы ответственности
InfraDrive — учебный распределённый файловый сервис, разделённый на два независимых слоя:
1. **Инфраструктурный слой (Ansible + Docker CE)** — отвечает за подготовку ОС Debian 13 (`trixie`), установку Docker, создание общей сети `infradrive_net`, выделение постоянных томов (persistent volumes), запуск контейнеров, настройку ограничений ресурсов и проверку готовности.
2. **Прикладной слой (FastAPI Backend + Storage Service)** — разрабатывается отдельно и отвечает за HTTP API, разбиение файлов на chunks, вычисление SHA-256, запись метаданных в Valkey, обеспечение фактора репликации `RF=2` и чтение из оставшейся реплики при отказе одной storage-ноды.

## 2. Компоненты инфраструктуры
* **Общая сеть `infradrive_net` (`bridge`)**: создаётся централизованно в `playbooks/site.yml` до старта контейнеров и обеспечивает внутреннее DNS-разрешение имён.
* **Valkey (`infradrive-valkey`)**: хранит метаданные файлов, карту размещения chunks и runtime-состояние в томе `infradrive_valkey_data` (`/data`) с включённым AOF (`appendonly yes`) и RDB-снимками. Бинарные данные файлов в Valkey не хранятся.
* **Три равноправные Storage-ноды (`storage-1`, `storage-2`, `storage-3`)**: каждая нода использует собственный изолированный том (`infradrive_storage_1_data..3`), смонтированный в `/data`. Поддерживаются два явно разделённых режима:
  * `storage_mode: "service"` (по умолчанию) — требует реального образа storage-сервиса (`storage_image`);
  * `storage_mode: "stub"` — инфраструктурный режим заглушек (`debian:trixie-slim`) для изолированного тестирования Docker-томов и сети.
* **FastAPI Backend (`infradrive-backend`)**: подключается к `infradrive_net` и запускается только при явно заданном реальном образе (`fastapi_image`).

## 3. Ограничения архитектуры
* Инфраструктура гарантирует воспроизводимое развёртывание и автоматический перезапуск контейнеров (`unless-stopped`), но не восстанавливает данные при физическом удалении Docker volume или выходе из строя диска хоста.
* В текущий scope проекта не входят Kubernetes, Docker Swarm, PostgreSQL, Prometheus и Grafana.
